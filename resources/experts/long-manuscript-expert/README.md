# 福帮手（long-manuscript-expert / 长文档写作与改稿专家）

把提纲、访谈、旧稿和零散素材整理成结构清晰的长文档，支持章节续写、限定范围改稿与成稿交付前检查。随包 9 个文体写作技能，覆盖学术、商业文案、公文汇报、法律合同、文学、科普、技术博客与研报等体裁。

## 能力定位

- **启动长文档**：用现有素材判断最合适的文档类型，给出手稿启动卡（建议目录、章节任务、实质性开篇、主要风险、一个推荐的下一步与可复制的续写口令）
- **限定范围改稿**：只续写或修改指定章节 / 段落，保留未选范围原文，并给出实质变更说明
- **成稿检查**：检查结构、连续性、可读性与交付准备；没有真实机器回执时，质量结论会明确标为建议性意见

## 技能（9 个）

| 技能目录 | 说明 |
|----------|------|
| `academic-paper-expert` | 学术论文写作：社科/理工科论文结构、APA/GB-T7714 引用规范、文献综述、摘要与学术润色 |
| `business-copy-expert` | 商业文案：品牌文案、营销邮件、产品描述、广告策划、社媒内容，基于 AIDA 模型与广告法合规 |
| `general-writer` | 通用写作：公文、周报、方案、邮件、文案、散文、新媒体稿件，含 7 维质量评分框架与 10 种文体适配矩阵 |
| `legal-contract-expert` | 法律合同：合同/协议/条款的起草与审查、必备条款完整性检查、权利义务对称性、高风险点防范；涉法律责任强制走 per-section 分章审查 |
| `poetry-prose-expert` | 诗歌与散文：现代诗、古体诗词、散文、随笔、文学评论 |
| `science-writing-expert` | 科普写作：面向大众的科学解释、科技评测、深度报道，基于科学传播理论与费曼学习法 |
| `stock-research-report-expert` | 证券/行业研究报告：行业深度报告、个股研究、动态点评、商业计划书、咨询交付物 |
| `tech-blog-expert` | 技术博客：技术文章、教程、架构解析、源码分析、开源项目文档 |

## 目录结构

```
long-manuscript-expert/
├── expert.md   # 人设正文 + frontmatter
├── skills/     # 9 个文体写作技能，每个 <技能名>/SKILL.md（部分带 references/、assets/、scripts/）
└── README.md   # 本文件
```

## 加载方式

- 会话按 `expertId` 绑定专家，取值就是本目录名 `long-manuscript-expert`，且必须与 `expert.md` frontmatter 的 `name` 一致。
- `skills/` 作为额外技能搜索路径挂载，每个技能目录必须有 `SKILL.md`；技能目录为空或缺少 `SKILL.md` 都会加载失败。
- 未声明 `expertType`，按单人设专家加载；目录下没有 `agents/`，不挂载成员。

## 已知限制

- `general-writer` 的 description 自称「L1 通用写作兜底专家……当 L0 路由未命中任何 L2 专家时作为兜底触发」。这套 L0/L1/L2 层级是技能自带的描述用语；在本专家里它由人设显式判断后调用，**不再是自动路由的一环**——只在「用户未指定文体 / 没有专门规范」时充当兜底。
- 9 个技能的正文用词、示例与规范（引用格式、评分框架、模板）自成一套，与本项目其他部分的约定未必一致。
- 9 个技能两两不重名，且与 `resources/skills/` 下的全局技能（`docx` / `frontend-design` / `meeting-notes` / `web-interface-guidelines`）均不重名。
